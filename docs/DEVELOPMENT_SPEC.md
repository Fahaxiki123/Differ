## 1. 文档目的

本文档是 Differ 项目的长期开发依据，用于固定产品边界、技术选型、架构原则、差异语义、质量门槛和变更机制。

任何实现如果与本文档不一致，必须先判断属于以下哪一种情况：

1. 实现缺陷：修正代码以符合规范。
2. 规范错误或描述不完整：先修正规范，再修改代码。
3. 产品要求发生变化：取得用户确认后，同步修改规范和代码。
4. 外部依赖或平台限制导致原方案不可行：记录证据、替代方案和影响，再更新规范。

不得通过口头约定或临时代码静默替代本文档中的正式决策。

## 2. 产品目标

Differ 是一款嵌入 TortoiseSVN 提交审阅流程的 Windows 差异查看工具。第一版的唯一主流程是：

1. 用户在 TortoiseSVN 提交窗口中查看待提交文件。
2. 用户双击其中一个文件。
3. TortoiseSVN 以“外部差异查看器”方式启动 Differ，并传入 BASE 文件、当前工作文件、显示名称和修订信息。
4. Differ 打开或复用主比较窗口，并为该文件建立一个工具栏下方的文件标签页。
5. 用户可继续在 TortoiseSVN 中双击其他文件；新的比较请求合并到同一窗口的标签栏。
6. 用户关闭单个标签页或整个 Differ 窗口后，继续在原 TortoiseSVN 提交窗口中操作。

Differ 的核心目标是准确展示这两个由 TortoiseSVN 指定的文件之间的代码、Word 或 Excel 差异。待提交文件选择、SVN 状态管理、仓库访问和最终提交均由 TortoiseSVN 负责。

产品追求与 Beyond Compare 相似的高效差异查看工作流，但不是其品牌、界面或资产的复制品。

当前定位是用户个人工作中的 SVN 提交前差异审阅工具。用户于 2026-10-24 授权代码及普通文本的连续编辑、块采纳、撤销重做与安全保存，具体以第 27 节为准；Office 保持只读。不扩展为 SVN 客户端、三方合并或通用文件管理器。

## 3. 初始产品范围

### 3.1 第一版必须支持

- Windows 10/11 x64。
- 注册为 TortoiseSVN 全局调用的外部差异查看器，使当前生效程序直接显示在 TortoiseSVN“差异查看器”主设置项中。
- 接收 TortoiseSVN 的 `%base`、`%mine`、`%bname`、`%yname`、`%brev`、`%yrev` 和 `%fname` 替换参数。
- 提供有明确名称的命令行参数，并兼容仅传入两个文件路径的调试调用。
- 比较 TortoiseSVN 提供的 `BASE` 文件和当前工作文件；主流程不依赖 `svn.exe`。
- 常见代码及纯文本文件的行级和词级差异。
- `.docx` 的段落、列表和表格内容差异。
- `.xlsx` 的工作表、行、单元格、值和公式差异，并以保留原工作表行列上下文的左右表格视图展示。
- `.xls`（NPOI HSSF）与 `.xlsm`（只读忽略 VBA 部件）的工作表与单元格差异，复用与 `.xlsx` 相同的工作表网格视图。
- `.csv` 的表格差异：RFC 4180 解析与行对齐，复用工作表网格视图。
- `.doc`（NPOI HWPF）与 `.rtf`（控制字剥离）的段落级文档差异，复用 Word 逻辑文档视图。
- 单个主比较窗口通过工具栏下方的标签栏承载多个文件；工具栏集中放置格式标识、显示/隐藏未修改项、上下一个差异和当前差异序号，标签栏只承载文件标签，内容区只保留格式专用差异视图。
- 代码和纯文本使用左右文本文档视图，保留行号、缩进、空白行、同步滚动和行内文字差异，不显示结构位置等通用模型字段。
- `.xlsx` 比较在内容区底部使用工作表标签切换各个工作表，不把多个工作表连续拼接成一个长列表。
- 无参数启动时显示 TortoiseSVN 集成状态、调用方式和故障排查入口，不显示工作副本扫描器。
- 完全离线比较本地传入文件，不主动访问仓库。
- 结构化适配器不覆盖或无法准确解析的任意文件回退到字节级二进制比较（左右十六进制视图），不存在“不支持”的空洞格式。

### 3.2 第一版明确不包含

- 由 Differ 扫描 SVN 工作副本或维护待提交文件列表。
- 由 Differ 查询 HEAD、判断工作副本是否过期或解释 SVN 冲突状态。
- 由 Differ 打开、控制或代替 TortoiseSVN 提交窗口。
- 由 Differ 执行提交、更新、还原、添加、删除等 SVN 操作。
- 将 `svn.exe` 作为主流程运行依赖。
- PDF 内容或页面级结构化差异。
- 图片像素级差异。
- 压缩包内容展开比较、注册表、音频元数据和数据库比较。
- Word 页面级高保真视觉差异。
- Excel 图表、数据透视表、外部数据连接和 VBA 代码差异。
- Office 原格式合并写回、三方自动合并及全语言 AST 合并。
- 自行保存 SVN 密码、证书或代理凭据。
- 云端上传、AI 分析或遥测。
- macOS、Linux 或移动端。

以上被排除结构化解析的格式仍按第 11.5 节回退到字节级二进制比较，而不是拒绝比较。

扩展以上范围前，必须更新本文档并评估依赖、性能、安全和测试成本。

## 4. 关键术语与差异语义

### 4.1 BASE

`BASE` 是 TortoiseSVN 调用外部差异查看器时通过 `%base` 传给 Differ 的原始文件。通常它代表当前工作文件所基于的工作副本版本。

默认比较关系：

```text
TortoiseSVN 提供的 BASE → TortoiseSVN 提供的当前工作文件
```

Differ 不自行定位、导出或猜测 BASE，也不把仓库 HEAD 替代为 BASE。

### 4.2 MINE

`MINE` 是 TortoiseSVN 通过 `%mine` 传给 Differ 的用户当前文件。界面显示名称优先使用 `%yname`，实际读取路径使用 `%mine`。

### 4.3 显示名称与修订

`%bname` 和 `%yname` 是 TortoiseSVN 生成的界面标题，不保证是纯文件名；例如它们可能包含“修订 123”或“工作副本”等说明。Differ 应原样用于两侧标题，但不得把它们当作文件路径。

`%brev` 和 `%yrev` 是可选修订信息。缺失时界面应自然降级，不得因此拒绝比较。

### 4.4 外部差异会话

一次外部差异会话只绑定一对输入文件，但一个主比较窗口可以通过顶部标签同时承载多个彼此独立的会话。关闭文件标签即结束该会话；关闭主窗口即结束全部会话。第一版不在 Differ 内维护“已复核”状态，TortoiseSVN 提交窗口仍是整个提交操作的上下文。

由于 TortoiseSVN 可能在它启动的外部进程退出后清理 BASE 临时文件，Differ 在把后续调用转交给已运行主实例前，必须先把 BASE 和当前文件复制到 Differ 自有的隔离会话目录。比较界面仍显示原始路径，但实际解析固定快照；关闭标签后删除该会话快照，异常退出遗留目录由后续主实例按过期策略清理。

## 5. 总体设计原则

1. **准确优先**：宁可明确显示“不支持”或“无法读取”，不得提供可能误导提交的差异结果。
2. **只读优先**：查看不得改变文件；仅代码/普通文本允许用户主动编辑后按第 27 节保存，Office、BASE、会话快照及 SVN 状态保持只读。
3. **离线优先**：两个本地输入文件的差异应在无网络时可用。
4. **职责清晰**：Differ 只查看差异；SVN 状态、文件选择和提交由 TortoiseSVN 负责。
5. **格式隔离**：每种文件格式通过独立适配器接入统一差异模型。
6. **渐进加载**：窗口立即显示两侧文件信息，结构解析在后台进行并支持取消。
7. **可追溯**：关键错误、外部进程和提交前校验应留下不含敏感内容的日志。
8. **可测试**：业务逻辑不得依赖 WPF 控件，格式解析和 SVN 交互必须可独立测试。
9. **最少依赖**：只引入有明确用途、许可证可接受且仍在维护的依赖。
10. **不破坏用户数据**：测试、缓存和临时文件不得覆盖用户原件。

## 6. 技术栈

### 6.1 基础平台

- 语言：C#。
- 目标框架：`.NET 10`。
- WPF 目标：`net10.0-windows`。
- 主运行平台：`win-x64`。
- UI 框架：WPF。
- 架构模式：MVVM。
- 首要界面语言：简体中文。
- 代码标识符、项目名和公共 API：英文。

### 6.2 推荐依赖

- `CommunityToolkit.Mvvm`：MVVM 基础设施。
- `Microsoft.Extensions.DependencyInjection`：依赖注入。
- `Microsoft.Extensions.Logging`：日志抽象。
- `DiffPlex`：文本差异算法和差异模型。
- `DocumentFormat.OpenXml`：Word、Excel OOXML 只读解析。
- `NPOI`（锁定 2.7.4）：`.xls`（HSSF）二进制格式解析，并作为 vendored HWPF 项目的底层依赖。自 2.8.0 起其 NuGet 二进制包改按 OSMF EULA 发布（年收入不低于 1 万美元的营利性使用者需缴纳维护费），2.7.5/2.7.6 又引入 NSax 依赖，因此固定使用最后一个纯 Apache-2.0 版本；升级前必须重新评估许可、兼容性与依赖树。
- `Differ.Vendor.HWPF`（仓库内 vendored 源码项目，非 NuGet 包）：`.doc`（Word 97）解析。NPOI 官方从未把 scratchpad/HWPF 发布为 NuGet 二进制；第三方 `ScratchPad.NPOI.HWPF` 按 NPOI 2.5.6 编译，与 2.7.x 二进制不兼容（`POIDocument` 抽象成员变化导致 `HWPFDocument` 类型加载失败）。因此把 NPOI 仓库 `scratchpad/HWPF` 子树（标签 `2.7.4-rc3`，即 2.7.4 发布二进制的源提交，nuspec 可证）以独立项目引入，仅被 `Differ.Formats.Word` 引用；项目内关闭 Nullable 与分析器，并在 csproj 注释中逐条登记对上游源码的少量兼容性修正（接口名、类名冲突、缺失抽象成员、`LittleEndian` 重载等）。运行时需注册 `System.Text.Encoding.CodePages` 提供程序（.NET 内置，无新增包）。
- `System.Configuration.ConfigurationManager`（4.5.0）：仅由 vendored HWPF 源码引用，主工程不得使用。
- xUnit：自动化测试。

正式开始开发时，所有 NuGet 版本必须集中锁定在 `Directory.Packages.props`，禁止各项目分散声明不一致版本。升级依赖时应记录兼容性验证结果。

### 6.3 明确禁止

- 不以直接读写 `.svn/wc.db` 作为正式 SVN 集成方案。
- 不使用 Word/Excel COM 自动化作为核心解析方案。
- 不在差异引擎中执行 Office 宏。
- 不让 View 或 ViewModel 直接运行 SVN 命令或解析 OOXML。
- 不在核心层引用 WPF 类型。

职责划分：

### Differ.App

- WPF 启动、窗口、资源和主题。
- View 和 ViewModel。
- 外部差异命令行入口、命令绑定、导航和用户交互。
- 无参数启动时的 TortoiseSVN 集成状态页。
- 只依赖公开应用服务，不包含格式解析细节。

### Differ.Core

- 统一差异模型。
- 文件类型识别。
- 外部差异请求模型与命令行参数解析。
- 缓存抽象、设置模型和通用错误类型。
- 不依赖 WPF、SVN 客户端或具体 Office SDK。

### Differ.Svn

- TortoiseSVN 安装和集成状态检测。
- 生成、安装、备份和恢复全局外部差异查看器配置，并备份、清除和安全恢复会覆盖全局路径的受支持扩展名高级绑定。
- TortoiseSVN 调用协议常量。
- 可选的未来 SVN 辅助能力不得进入第一版主流程。
- 不包含文件格式差异逻辑。

### Differ.Formats.*

- 将具体文件解析为统一结构。
- 调用通用差异算法。
- 输出 `DiffDocument`，不直接控制界面。
- `Differ.Formats.Word` 同时承载 `.docx`（Open XML）与 `.doc`（vendored HWPF）适配器，两者共享块对齐与比较逻辑。
- `Differ.Formats.Excel` 同时承载 `.xlsx`/`.xlsm`（Open XML）与 `.xls`（NPOI HSSF）适配器，共享工作表中间模型与比较引擎。
- `Differ.Formats.Binary` 是不支持结构化解析格式的字节级回退适配器，在适配器链中始终排在最后，`CanHandle` 对任意路径返回真。

### Differ.Vendor.HWPF

- 仓库内 vendored 的 NPOI scratchpad/HWPF 源码副本（Apache-2.0），提供 `.doc` 解析能力，见第 6.2 节的引入原因与版本锁定说明。
- 仅被 `Differ.Formats.Word` 引用；关闭 Nullable 与分析器以保持上游源码原貌，兼容性修正集中在 csproj 注释中登记。
- 不包含任何 Differ 业务逻辑，也不被其他项目直接引用。

### Tests

- 单元测试、格式回归测试、性能基准和隔离 SVN 集成测试。

## 8. 核心数据流

```text
用户在 TortoiseSVN 提交窗口双击文件
    ↓
TortoiseSVN 替换外部差异参数并启动 Differ
    ↓
Differ 校验 BASE/MINE 并创建只读会话快照
    ↓
首个进程创建主比较窗口；后续进程通过当前用户会话内的命名管道转交请求后退出
    ↓
主窗口新增或聚焦工具栏下方的文件标签，并根据文件名或当前文件扩展名选择格式适配器
    ↓
后台只读解析两个文件并生成统一差异模型
    ↓
WPF 在当前文件标签中展示双栏差异；Excel 使用底部工作表标签切换
    ↓
用户关闭 Differ，返回原 TortoiseSVN 提交窗口
```

解析和比较操作应支持异步取消。窗口关闭时必须取消仍在进行的解析，避免后台任务继续占用临时文件。

## 9. TortoiseSVN 集成规范

### 9.1 外部差异调用协议

TortoiseSVN 支持在外部差异程序命令行中使用 `%` 前缀的替换参数。Differ 第一版使用以下参数：

| TortoiseSVN 参数 | Differ 含义 | 必需性 |
|---|---|---|
| `%base` | 原始 BASE 文件路径 | 必需 |
| `%mine` | 当前工作文件路径 | 必需 |
| `%bname` | BASE 侧显示标题 | 可选 |
| `%yname` | 当前文件侧显示标题 | 可选 |
| `%brev` | BASE 修订 | 可选 |
| `%yrev` | 当前侧修订 | 可选 |
| `%fname` | 原始文件名 | 可选 |

推荐注册命令：

```text
"<安装目录>\Differ.App.exe" --base %base --mine %mine --base-name %bname --mine-name %yname --base-revision %brev --mine-revision %yrev --file-name %fname --source tortoisesvn
```

命令行解析不得依赖参数顺序。为开发和故障排查提供以下兼容入口：

```text
Differ.App.exe "<base-path>" "<mine-path>"
```

TortoiseSVN 在命令不含 `%` 占位符时会按旧版协议追加位置参数，Differ 必须兼容恰好 6 个位置参数的调用：第 1、2 个为 BASE 和当前工作文件路径，第 3、4 个为两侧显示标题，第 5、6 个为两侧修订信息。其他数量的位置参数仍视为错误。

两个文件路径是唯一必需输入。缺少文件、路径不存在、两侧均为目录或格式不受支持时，必须显示可操作错误，不得打开空白比较页。

### 9.2 全局差异查看器注册

使用 TortoiseSVN 设置页直接展示的全局“差异查看器”命令，即当前用户注册表 `Software\TortoiseSVN` 下的 `Diff` 值。安装完成后，用户必须能在 TortoiseSVN 主设置页直接确认、复制或手工修改当前生效的 Differ 路径和参数。

不得修改 `DiffProps`、`DiffViewer` 或 Merge Tool 配置：Differ 比较文件内容，不接管 SVN 属性差异、统一补丁查看器或合并工具。

TortoiseSVN 的“差异查看器 → 高级”按扩展名配置优先于全局 `Diff`。因此，全局注册只有在全部受支持扩展名都没有高级覆盖时才算完整生效；否则会出现设置页显示 Differ、实际仍由隐藏扩展名工具接管的歧义。

用户明确执行“安装到 TortoiseSVN”时：

- 读取并备份全局 `Diff`、旧备份以及全部受支持扩展名的当前高级配置。
- 写入全局 Differ 命令，并删除全部受支持扩展名的非空高级覆盖，使代码、文本、Word、Excel 和 CSV 统一落到设置页可见的全局路径。
- 重复安装时，若用户在上次安装后又为某个受支持扩展名配置了新工具，本次显式安装应把该当前值更新为未来恢复基线，再清除该覆盖；不得静默保留并导致全局路径失效。
- 不属于 Differ 支持范围的高级扩展名配置保持不变。
- 完整安装状态同时要求全局 `Diff` 等于当前 Differ 命令，且全部受支持扩展名高级覆盖为空。

Differ 继续按文件内容和扩展名识别文本、Word、Excel；结构化解析失败时按第 11.5 节回退字节比较并明确提示无法提供结构化结果，不得尝试以错误格式解释。

### 9.3 配置安全与恢复

- 注册范围为当前 Windows 用户。
- 写入前读取全局 `Diff` 以及全部受支持扩展名的高级配置。
- 对全局值和受支持扩展名高级值生成滚动式本地备份：单一带 `CreatedUtc` 时间戳的备份文件记录全部原始值，重复安装时更新恢复基线而不是堆积历史副本，并提供恢复能力；备份必须包含空值，以便区分“原本未配置”和“尚未记录”。
- 重复安装相同命令应幂等。
- 卸载或恢复时只修改仍等于 Differ 已安装命令的全局 `Diff`；若用户后来手工修改全局路径，必须安全跳过。
- 对高级扩展名，只有当前值仍为空时才恢复非空备份；若用户安装后重新配置了该扩展名，必须安全跳过并保留备份。
- 备份模型必须兼容旧版扩展名备份；旧版备份可按原有“当前仍等于旧 Differ 命令才恢复”的规则单独恢复，也可在显式安装新版时升级为包含全局值和全部受支持高级值的新模型。
- 便携发布目录移动后原注册路径会失效；集成状态页必须检测并提示重新注册。

### 9.4 参数和路径安全

- 使用 .NET 提供的命令行参数数组，不通过 `cmd.exe` 或 PowerShell 再解释参数。
- 支持空格、中文和长路径。
- BASE 可能位于 TortoiseSVN 临时目录，必须在窗口生命周期内只读使用。
- 多文件聚合时必须在转交请求前创建 Differ 自有的 BASE/MINE 快照，避免次进程退出后 TortoiseSVN 清理 BASE 导致已打开标签失效。
- 文件类型选择优先使用 `%fname` 或 `%mine` 的扩展名，不能只依赖 BASE 临时文件扩展名。
- 不记录文档正文、单元格内容或未处理的完整命令行。

### 9.5 BASE 预处理

TortoiseSVN 可能在比较 BASE 前处理关键字展开和本机行尾。Differ 比较收到的实际文件内容，不重复执行 SVN 关键字或行尾转换，并在文档中把该行为归属给 TortoiseSVN 配置。

### 9.6 主流程依赖

主流程不定位或执行 `svn.exe`，不读取 `.svn/wc.db`，不访问仓库，也不要求 Differ 知道工作副本根目录。TortoiseSVN 本身不是解析依赖：将任意两个受支持文件传给兼容入口也应能比较。

### 9.7 提交边界

Differ 是由已经打开的 TortoiseSVN 提交窗口临时启动的查看器。每次调用仍只接收一个文件的 BASE/MINE，不接收待提交集合；主实例只负责把多个独立调用聚合为顶部文件标签。Differ 不保存 SVN 凭据、不显示“继续提交”按钮，也不推断关闭窗口后的提交结果。用户关闭 Differ 后，控制权自然返回 TortoiseSVN。

## 10. 统一差异模型

外部调用先规范化为：

```text
ExternalDiffRequest
├─ BaseFilePath
├─ MineFilePath
├─ BaseDisplayName
├─ MineDisplayName
├─ BaseRevision
├─ MineRevision
└─ OriginalFileName
```

应用层再把它映射为格式适配器使用的 `DiffRequest`。格式适配器输出统一的逻辑模型，至少包含：

```text
DiffDocument
├─ FileKind
├─ BaseRevision
├─ CurrentSnapshot
├─ Summary
├─ TabularSections[]
│  ├─ Key
│  ├─ Columns[]
│  └─ Rows[]
│     ├─ OldIndex / NewIndex
│     ├─ Kind
│     └─ Cells[]
│        ├─ ColumnKey
│        ├─ OldValue / NewValue
│        └─ Kind
└─ DiffNode[]
   ├─ StableId
   ├─ Path
   ├─ Kind: Unchanged / Added / Deleted / Modified / Moved / Conflict
   ├─ OldValue
   ├─ NewValue
   ├─ Children
   └─ Metadata
```

要求：

- UI 只能依赖统一模型和专用展示模型。
- 每个差异节点应有稳定定位信息，用于“上下一个差异”和复核追踪。
- 适配器无法准确理解的内容应输出 `Unsupported` 或警告节点，不得静默丢弃。
- 摘要计数必须从最终模型计算，不重复维护另一套计数。
- 具有天然行列结构的格式可同时输出 `TabularSections`。表格模型必须与 `DiffNode` 使用同一次行对齐结果，禁止 UI 再次解析 Office 文件或按单元格地址猜测原表格。
- `TabularSections` 必须保留两侧真实行号、统一列顺序、空白单元格和单元格差异类型，使展示层能够稳定构建左右严格对齐的只读表格。

## 11. 代码和文本差异规范

### 11.1 初始格式

支持常见纯文本、配置和代码扩展名，包括但不限于：

```text
.txt .md .log .ini .config
.cs .java .cpp .c .h
.js .ts .jsx .tsx .vue
.py .lua .go .rs
.xml .json .yaml .yml
.html .css .scss .sql
```

未知扩展名应先执行文本/二进制检测，而不是仅依赖扩展名。

### 11.2 编码

- 优先识别 BOM。
- 支持 UTF-8、UTF-16 LE/BE。
- 对无 BOM 文本进行可解释的编码探测，并允许用户手动切换编码。
- 工具栏更多菜单提供高级规则入口，保留自动、UTF-8、UTF-16 LE/BE、GB18030编码及忽略空白、大小写、行尾、格式选项，仅显示适用项。编辑会话的重算基于当前内存文档，其他视图基于固定快照；取消旧请求，不允许过期结果覆盖。
- 中文 Windows 环境需考虑 GBK/GB18030。
- 无法可靠解码时不得替换字符后继续假装结果准确，应显示编码警告。

### 11.3 差异算法

- 第一层按行对齐。
- 第二层对修改行做词或字符级高亮。
- 忽略空白、大小写和行尾符是用户选项。
- “忽略”只影响匹配和突出显示，原始内容仍应可查看。
- 行尾符和文件末尾换行变化应作为文件元数据提示。
- 大文件应延迟计算、折叠未修改区域并使用虚拟化展示。

DiffPlex 负责差异算法；业务模型不得直接依赖其 WPF 控件类型。

### 11.4 文本文档差异视图

代码和纯文本的主视图必须表现为完整的左侧只读 BASE 与右侧可编辑文本文档，而不是把统一差异模型直接投影成业务表格；本轮按第 27 节替换逐行表格编辑路线：

- 左侧 BASE、右侧当前工作文件，各自只显示行号沟槽和文本正文。
- 两侧共享同一对齐行序列、固定行高和等宽字体；新增或删除行在另一侧保留空占位，后续内容不得上下错位。
- 保留原始缩进、空白行和长行水平滚动；两侧垂直和水平滚动都必须同步，避免长行在左右视图中错位到不同的列区间。
- 新增、删除、修改使用行号标记、淡色背景和行内文字片段共同表达，禁止常驻“类型”“结构/位置”等辅助列挤占正文。
- 选中差异行后，底部提供可折叠的完整内容详情，展开时显示该行两侧完整内容和行内文字差异，长行允许换行或滚动查看；文本首次默认折叠，展开状态与高度按格式记忆，选择变化不得自动展开。详情区文本必须支持鼠标选中和字符级复制，见第 14.5、14.8 节。
- 语法高亮可在后续版本加入，但不得成为差异准确性或 TortoiseSVN 调用的依赖。
- Word 继续使用文档结构适配器和独立的逻辑文档视图，不得伪装成代码编辑器。

### 11.5 二进制差异规范

- 结构化适配器（文本、Word、Excel）不适用或无法准确解析的任意文件，必须回退到字节级二进制比较；文本适配器按内容探测出二进制时也必须移交二进制适配器，不得输出“二进制不支持”的拒绝结果。
- 回退必须保留明确的结构化解析失败提示；只处理已知格式损坏/解析失败，不吞掉取消、权限、文件丢失和资源限制错误。二进制自身大小限制继续生效。
- 二进制视图复用左右等宽文本视图的滚动同步、导航和复制能力，每行固定 16 字节，行号沟槽显示该行的字节偏移；新增或删除的行在另一侧保留空占位。
- 行对齐以 16 字节行的签名序列进行，复用统一的序列对齐算法；超大序列沿用前缀/后缀剥离和线性锚点回退。
- 修改行必须按字节粒度做片段差异，高亮边界落在完整字节上，不得只高亮半个字节的单个十六进制字符。
- 两侧字节完全相同时直接判定“两侧文件相同”，跳过行对齐计算。
- 二进制文件没有编码和行尾概念，不得为其产生编码或行尾警告。
- 文件大小上限、行宽等参数集中配置在统一阈值中；超过上限必须给出可操作错误，不得静默截断比较。
- 二进制差异视图第一版不承诺提供 ASCII 侧栏、字节序切换或结构偏移注释。

## 12. Word 差异规范

### 12.1 格式范围

第一版承诺 `.docx`（Open XML SDK）、`.doc`（NPOI HWPF）和 `.rtf`（控制字剥离）。`.doc` 仅承诺段落与表格单元格的文本提取，不承诺图片、嵌入对象、页眉页脚和复杂排版的高保真还原；无法准确提取的部分应产生警告。`.rtf` 按纯文本控制字规则提取段落正文，跳过字体表、颜色表、样式表等目标组；`\uN` 转义必须还原为对应字符，`\'hh` 字节按 GB18030 解码。`.docm`、`.dotx` 等其余格式必须单独评估后再加入。

### 12.2 解析原则

- 使用 Open XML SDK 只读打开。
- 不调用 Word COM。
- 不执行宏。
- 不保存或重打包源文件。
- XML 解析必须禁用不安全外部实体。
- 对损坏、加密或不受支持的文档给出明确错误。

### 12.3 逻辑结构

至少提取：

- 文档标题和普通段落。
- 标题级别和段落样式标识。
- 有序/无序列表项。
- 表格、行、列和单元格文本。
- 页眉、页脚和超链接文本。
- 图片部件的增加、删除和内容哈希变化。
- 修订标记的存在及基本统计。

### 12.4 比较方式

1. 先按逻辑块对齐段落、列表和表格。
2. 对已对齐的文本块做词级差异。
3. 表格先对齐行，再对齐单元格。
4. 移动但内容相同的块可在后续版本识别；第一版允许表示为删除加新增。
5. 样式和格式差异作为独立开关，不能与文本修改混为一类。

单元格内的内容控件和嵌套表格必须递归提取；无法理解的子结构必须警告，不能产生“无差异”的静默漏报。表格行列、合并跨度及内容归属属于结构语义，不受默认关闭的格式开关影响；行插入后仅位置偏移的相同内容不得被放大为全表修改。RTF 必须保留域的可见结果而不执行域指令，并按分组作用域的 `\ucN` 正确跳过 Unicode 回退字符。

TortoiseSVN 外部差异窗口第一版默认关闭 Word 样式/格式比较，只统计正文和结构内容。格式开关关闭时不得把样式元数据变化计入默认差异摘要。

Word 正文以还原原始排版为优先，因此不设置行号沟槽，也不再额外保留一条常驻的页面/差异标记沟槽；差异位置统一由主比较区左侧的可交互缩略概览表达。Word 视图没有独立详情区，正文内容通过第 14.5 节的右键菜单和 `Ctrl+C` 按段落或表格行复制。缩略概览的选中反馈只在按住期间显示，当前可视范围则允许以低对比滑块持续提示；按下并拖动时必须随指针经过的位置连续跳转，单击仍应跳转到对应正文。正文行只显示一次短暂定位闪烁并自动清除，不得保留常驻蓝色定位线、持续选中底色或重复标记；定位反馈必须使用不参与测量的覆盖层或固定尺寸样式，不得改变段落高度、内边距或上下行间距。

### 12.5 修订记录

第一版默认比较“最终有效文本”：

- 普通文本和插入内容计入当前文本。
- 删除修订不计入当前有效文本，但应在元数据中提示文档包含未接受修订。

如果实现“显示所有修订”模式，必须作为独立功能更新规范和测试。

### 12.6 非目标

内容差异不等于页面视觉差异。第一版不承诺精确比较：

- 分页变化。
- 字体渲染变化。
- 行距和字符间距。
- 浮动对象位置。
- Word 不同版本造成的排版差异。

## 13. Excel 差异规范

### 13.1 格式范围

第一版承诺 `.xlsx` 与 `.xlsm`（同一 Open XML 只读管道；`.xlsm` 的 VBA 部件忽略，不执行也不比较宏代码，符合第 13.2 节不执行宏的约束）以及 `.xls`（NPOI HSSF，复用与 `.xlsx` 相同的中间模型与比较引擎）。`.xlsb` 与外部数据连接不在第一版范围。

### 13.2 解析原则

- 使用 Open XML SDK 只读打开。
- 不调用 Excel COM。
- 不执行公式计算或宏。
- 不把公式缓存值当作实时计算结果。
- 不修改工作簿计算模式或缓存。

### 13.3 比较对象

至少比较：

- 工作表新增、删除、重命名和顺序变化。
- 行新增、删除和移动。
- 单元格地址、语义类型、显示值和必要的原始值。
- 公式文本及其缓存值。
- 合并区域。
- 注释或批注。
- 隐藏行、隐藏列。
- 可选的基础格式：字体、填充、边框、对齐和数字格式。

格式变化必须能单独过滤，避免掩盖数据变化。

TortoiseSVN 外部差异窗口第一版默认关闭 Excel 基础格式比较，只统计工作表结构、值、公式及其他明确支持的内容变化。实测工作簿可能因保存工具重写样式元数据；不得让这类变化把一个有效单元格内容差异放大成大量修改。

Excel 的 `sharedStrings.xml` 索引属于 OOXML 包内部引用，不是单元格内容。保存工作簿后，即使可见文本完全不变，共享字符串表的插入或重排也可能让大量单元格的原始索引改变。默认差异判断必须先解析索引并比较实际显示文本，不得把共享字符串索引变化计为内容修改；公式缓存值、数值和布尔值等具有实际语义的原始值仍按其解析后语义比较。

### 13.4 行对齐

不得只按单元格坐标直接比较整个工作表。插入一行时，应先通过行内容签名进行序列对齐，再比较对应单元格，以减少后续所有行被误报为变化。

初始行签名可由以下内容组合：

- 非空单元格数量。
- 规范化文本和值。
- 公式标识。
- 关键列内容。

算法不能可靠对齐时应明确退回坐标比较并显示提示。

对齐成功但行号发生偏移的行（例如上方插入一行导致后续行整体下移）仍视为未修改，不得升级为“移动”差异或计入差异摘要；两侧表格继续显示各自真实的 Excel 行号，使偏移本身可见。“移动”语义只用于工作表顺序变化等结构级差异。

用户可显式指定 Excel/CSV 的关键列（如 A 或 A,C）；键值按列的语义内容组成，不按样式索引或显示截断值匹配。Excel 先建立逻辑列映射，合法唯一键保持配对；空键、重复键仅在局部降级并提示，不让异常值破坏其余已确认匹配。表头不进入数据键检查。真实重排与插入后坐标偏移分别表达；字符串 0012 不默认等于数值 12。CSV 保持现有按列配置兼容。

### 13.5 公式

- 公式文本变化必须被标记，即使缓存值相同。
- 共享公式必须按主公式、共享索引和相对/绝对引用展开为每个单元格的实际公式；共享与独立存储形式等价时不报差异。不能可靠展开时给出警告或明确解析失败，禁止把空公式当作完整结果。
- 缓存值变化也应独立标记。
- 不在 Differ 中重新计算公式。
- 外部引用无法解析时显示引用信息，不尝试访问外部工作簿。

### 13.6 工作表差异视图

Excel 比较的主视图必须是原工作表上下文中的左右表格，而不是“结构位置、旧值、新值”组成的扁平差异清单：

- 左侧显示 BASE，右侧显示当前工作文件；两侧使用相同的工作表、列顺序、列宽策略和对齐行序列。
- 显示解析到的工作表有效区域，包括未修改的上下文行和单元格；行号使用两侧各自的真实 Excel 行号，列标题使用 `A`、`B`、`C` 等工作表列名。
- 有效区域内部省略存储的空白行列必须保留；填充范围和总单元格数受集中资源预算限制，超过预算给出可操作错误，禁止静默裁掉中间上下文。文本、数值等类型按语义规范化，样式比较依据解析后的实际格式，不能直接比较内部存储 token 或样式索引。
- 行新增、删除或移动时，两侧通过同一个对齐行占位，确保后续上下文不会垂直错位。
- 默认显示未修改上下文；关闭“显示未修改”后按差异行过滤，但不得把多个工作表拼接到一起。
- 变化背景只作用于发生变化的单元格及其行号状态标记，不得用整行实色背景淹没未变化单元格。
- 已修改单元格必须在单元格内部继续做字符或词片段差异，把真正新增、删除或替换的文字单独着色和加重；不得只依赖单元格底色。单元格只保留一层语义背景，文字片段不得再叠加第二层背景色。
- 单元格文本不自动换行，使用一致的内边距、基线和固定行高；过长内容截断并通过工具提示查看完整值，避免左右文本视觉错位。
- 两侧垂直滚动必须同步；在列集合和列宽一致时水平滚动也应同步。工作表标签切换后必须重新建立相同列集合和宽度。
- 公式单元格在表格内优先显示公式文本；已保存缓存值可通过工具提示或详情查看，不得把调试式缓存说明直接拼进主表格造成列宽失真。
- 选中任一单元格时，主表下方必须提供独立、可折叠的单元格详情区：标明两侧单元格地址，展开时完整展示 BASE 和当前内容，并继续保留字符或词片段差异。Excel 首次紧凑展开，用户折叠后不随选择自动展开，展开状态与高度按格式记忆。详情区不得使用主表格的列宽截断规则，并且必须支持鼠标选中和字符级复制，见第 14.5、14.8 节。
- 差异导航定位到一行时，默认选择该行第一个变化单元格并更新详情；用户点击其他单元格后，左右选择和详情必须同步。
- 工作表名称/顺序、隐藏列、合并范围等结构差异必须计入对应工作表，并进入统一上下差异导航。选择结构差异时，使用紧凑的按需双侧详情显示具体变化；主区域始终保留工作表网格。差异计数与实际导航目标采用一致口径。

### 13.7 CSV 比较规范

- 按 RFC 4180 规则解析：双引号围拢字段、引号内双写引号转义、允许字段内换行；分隔符固定为逗号，不做分隔符自动探测。
- 复用文本侧的编码探测与警告；第一版不把首行当作表头特殊处理，统一作为数据行参与对齐。
- 行对齐复用统一序列对齐算法，对齐后逐列比较；列按两侧最大列数以 Excel 列名（A、B、C…）命名。
- 对齐成功且内容一致仅行号偏移的行同样视为未修改，与第 13.4 节一致。
- 输出 `TabularSections` 复用工作表网格视图与底部工作表标签，单一工作表命名为 `CSV`。
- CSV 必须保留字段总数、尾部空字段、全空记录与有效区域内部空白，不能把列数或记录数变化吞掉；单纯末尾记录终止换行不新增虚假空记录。

## 14. UI 与交互规范

### 14.1 外部差异窗口

主比较窗口聚焦当前选中的一对文件，不显示待提交文件列表、HEAD 状态或提交按钮。推荐结构：

- 最顶部：单条38 DIP工具栏。集中保存分裂按钮、撤销/重做、全部/差异/上下文选中按钮、上下块/唯一序号、查找/刷新、编辑模式、主题及更多；高级编码/忽略/工作表规则收在更多入口，去掉常驻比较选项按钮。文本专用命令按格式显示，工具栏不重复完整文件名。
- 工具栏下方：独立的文件标签栏。每个标签显示文件名、差异状态并可独立关闭，不与操作按钮争夺同一行空间。
- 标签栏下方：主比较区。左侧提供与当前差异集合对应的纵向可交互缩略概览，用不同长度的细线和差异颜色表达文档结构与差异分布；点击概览位置必须选中对应差异并滚动正文到相同逻辑位置，按住并纵向拖动时必须随着指针跨过的聚合区间连续更新目标。该交互在文本、Word 和 Excel 视图中保持一致。右侧放置格式专用只读差异视图。缩略概览不得替代正文行号、表格行列或差异详情；Word 正文不再重复设置同义的页面/差异标记栏。
- 主比较区底部：使用紧凑的一行 BASE/当前文件摘要，仅保留短文件名和侧别；完整路径与完整修订信息放入工具提示或按需详情，不设置常驻的大尺寸元数据卡片。
- 内容区主体：左右等宽、使用中线分隔的格式专用只读差异视图；文本使用第 11.4 节的文本文档视图，Word 使用逻辑文档视图，Excel 使用第 13.6 节的原工作表双栏矩阵。
- 内容区下部：文本和 Excel 通过可折叠详情展示当前行或单元格的完整双侧内容；详情与主视图使用同一选择状态，默认展开策略与布局记忆见第 14.8 节。
- Excel 内容区底部：按工作簿顺序排列工作表标签，标签显示工作表名和该表差异数量；一次只展示当前工作表，禁止把多个工作表连续拼接到同一滚动区。
- 底部：使用单行状态栏显示当前差异序号、解析状态、摘要和加载耗时。非阻断警告只使用紧凑计数与工具提示或按需详情，不得占用常驻的大块垂直空间。

窗口标题应表达当前文件名和比较关系。双击 TortoiseSVN 中不同文件时，后续调用通过当前 Windows 用户和桌面会话范围内的单实例通信合并到现有主窗口，并自动选中新文件标签，不创建多个独立比较窗口。重复打开同一路径时优先聚焦已有标签；若 BASE 修订或快照内容不同，可建立新的独立标签。

### 14.2 无参数启动页

用户直接运行 `Differ.App.exe` 时显示轻量集成页，至少包含：

- 当前可执行文件路径。
- TortoiseSVN 是否已安装。
- 支持的文件类型。
- 外部差异命令模板。
- 集成是否指向当前可执行文件。
- 安装、恢复或打开 TortoiseSVN 设置的入口。

该页面不得伪装成文件管理器或工作副本扫描器。可提供“选择两个文件进行测试”，但它只是诊断入口，不是产品主流程。

### 14.3 差异颜色

- 新增：绿色系。
- 删除：红色系。
- 修改：黄色或橙色系。
- 冲突：高对比警示色。
- 未修改：中性色。

颜色不能是唯一信息来源，必须同时使用符号、文字或边框，以支持色觉障碍用户。

逻辑行视图应使用行号沟槽、边框或状态条表达变化，选中后不得退化为系统默认灰色而丢失变化语义。选中或定位反馈不得改变控件边框厚度、内边距、高度或行间距。文本、Word 和 Excel 的差异内容只使用一层行、段落或单元格语义背景；片段级变化使用前景色和字重表达，不再叠加第二层片段背景。Excel 表格不得整行铺设高饱和底色：新增、删除、修改、移动和冲突只在对应单元格及行号状态标记中分别使用绿色、红色、淡红/琥珀、蓝色和橙红色，并在修改单元格内部继续突出真正变化的文字片段。工作表标签和文件标签对“包含差异”“当前选中”也必须同时使用颜色与文字/计数表达。

全部差异语义色、界面底色、边框和文字色必须集中为设计令牌，统一定义在 `src/Differ.App/Themes/Light.xaml` 与 `Dark.xaml` 两套 `ResourceDictionary` 中并使用完全一致的资源键；XAML 通过 `DynamicResource` 引用，自绘控件（差异缩略概览、行内片段前景）在渲染时从主题资源查找颜色，不得在 XAML 或 C# 中散落硬编码色值。产品提供浅色与深色两套主题：默认跟随 Windows 系统主题，并在比较窗口工具栏提供可见的手动切换入口；主题字典必须在首个窗口创建前按系统设置加载，避免先显示浅色再切换造成闪烁；运行期间监听 Windows 用户偏好变化并同步系统主题，手动切换必须即时生效。主题服务使用依赖注入的应用级实例，禁止通过静态可变状态或 `Application.Current` 隐式共享测试状态，不得生成仅用于排查主题切换的常驻诊断文件。主题切换不得改变布局、行高、内边距或差异语义。两套主题必须覆盖相同的资源键集合，任一主题缺键都应由自动化测试判定失败。深色主题下同样遵守“单层语义背景 + 片段前景色”和“颜色不可作为唯一信息来源”的既有约束。

### 14.4 键盘操作

统一支持：

- `F7`：上一个差异。
- `F8`：下一个差异。
- `F5`：保留 BASE，刷新当前工作文件快照。
- `F9`：切换浅色/深色主题。
- `Ctrl+F`：查找；面板内 `Enter` / `Shift+Enter` 跳转下一个 / 上一个匹配。
- `Ctrl+G`：定位行号或单元格。
- `Ctrl+Tab` / `Ctrl+Shift+Tab`：切换下一个 / 上一个文件标签。
- `Ctrl+滚轮`：缩放正文，缩略预览宽度保持不变。
- `Ctrl+U`：显示或隐藏未修改项。
- `Alt+Left`：聚焦 BASE 侧内容。
- `Alt+Right`：聚焦当前工作文件侧内容。
- `Ctrl+W`：关闭当前文件标签；只有一个标签时关闭窗口。
- `Esc`：优先关闭查找、定位或标签筛选局部界面；无局部界面时关闭比较窗口。

快捷键不得拦截文本选择、复制等系统操作；工具栏按钮和工具提示必须提供不依赖记忆快捷键的等价入口。

### 14.5 选中与复制

差异内容必须可以取出来，而不是只能在窗口里阅读。三种视图统一遵守：

- 底部详情区必须支持鼠标拖动选中任意字符范围，并支持系统原生的复制路径；选中不得改变文字位置、行距或片段着色。
- 主视图行、单元格保持虚拟化的轻量渲染，不为了字符级选中把每一行换成可编辑文本控件；主视图通过右键菜单和 `Ctrl+C` 提供行级或单元格级复制。
- 右键必须先把光标下的行或单元格提升为当前选择，再打开菜单，避免复制到上一次的选择。没有可复制目标时不弹出菜单。
- 复制菜单至少提供 BASE 侧、当前侧和两侧对照三种结果；两侧对照使用制表符分隔，便于直接粘贴进表格。Excel 额外提供整行复制。
- 使用模板列的表格必须关闭控件内置的剪贴板复制模式，改由显式命令输出真实文本，避免复制出空字符串。
- 复制只写入纯文本，不写入文件路径、修订号或日志内容；剪贴板被其他进程占用时静默失败，不得中断比较窗口。

### 14.6 状态表达

必须清楚区分：

- 正在解析。
- 两侧文件相同。
- 存在差异。
- 输入文件不存在或已被 TortoiseSVN 清理。
- 不支持的格式。
- 解析失败。
- 文档包含不支持或无法准确解释的结构。

禁止只用“失败”或无内容空白页表达不同错误。

### 14.7 个人审阅效率与缩略预览

- 左侧预览参考用户录屏 `Recording-20260919-173301.mp4` 的窄条、悬停局部放大和浮动内容预览，以及编辑器 minimap 的可视范围指示。保持现有浅深主题；预览用轻量笔画表达文本/表格密度、语义色标出差异，不能将少量内容强行拉满整个高度造成空洞刻度。悬停预览显示当前位置及附近真实双侧内容，不能使用无信息的占位装饰；浮层不参与主布局、不截断到屏幕之外，鼠标离开后隐藏。
- 预览与正文滚动双向同步。当前可见区低对比显示；单击定位、按住拖动连续定位，鼠标滚轮按正文习惯滚动。大量内容按像素桶聚合，绘制量受视口限制；不得每一行创建 WPF 控件。文字/表格详情和主视图仍是完整内容的权威展示。
- `Ctrl+F` 打开查找，支持前后匹配、大小写与仅差异范围；`Ctrl+G` 定位行号或单元格（例如 A123）。查找和定位必须跨工作表正确选择目标；若目标处于折叠区须先展开。输入/浮层打开时 `Esc` 优先关闭该局部界面，再次按下才关闭比较窗口。
- 在“全部”和“仅差异”之外提供“差异上下文”模式，默认保留前后 3 行/逻辑块；连续未修改区显示可展开的折叠行和真实隐藏数量。展开可恢复全部内容，导航与行号仍引用原始坐标；表格行与 Word 表格行不得拆散。
- 字体缩放提供可见入口和 `Ctrl+滚轮`，限制合理范围并同步双侧布局；在用户本地数据目录记住缩放、窗口尺寸/位置、详情区高度，损坏设置安全回退，窗口不得恢复到屏幕之外。
- `F5` 只重新获取当前工作文件的只读快照，继续使用已打开的 BASE 快照，更新内容哈希与时间提示；成功前保留旧结果，失败可重试，不自行重新定位 BASE，不写入源文件。关闭/切换选项时取消过期刷新；所有新旧快照按会话生命周期清理。
- 多文件支持 `Ctrl+Tab` / `Ctrl+Shift+Tab`、按文件名筛选标签、关闭其他和关闭全部；关闭仍只释放相应会话，不操纵 SVN 提交选择。
- 比较规则可按格式保存为本地预设，包含编码/忽略/格式/关键列选项；明确显示当前启用的规则，可恢复默认。默认准确性优先，未显式保存的临时规则不得影响其他文件。预设不得保存文档内容、文件路径或 SVN 凭据。
- 可主动导出当前文件差异的本地 HTML 报告或选中差异的文本；目标由用户选择，正文和标题必须 HTML 编码、报告不包含脚本或外部资源，不自动发送或上传。导出路径不得覆盖 BASE、工作文件或活动快照。
- 新功能以紧凑工具栏、局部面板和菜单承载，避免扩大常驻顶栏高度或用辅助卡片挤压正文。

### 14.8 克制的阅读界面与详情布局

用户于 2026-09-24 批准在现有 WPF 架构中实施界面优化，设计依据为 `artifacts/design/2026-09-24-ui-proposal/GDDiff-UI设计方案.md`。保留双栏、单实例多文件标签、Excel 工作表标签、左侧 minimap 与全部只读比较能力，不新增文件树、仓库历史、提交或合并操作。

- 默认字号缩放下，工具栏 38 DIP、文件标签 30 DIP、文本/Excel 侧标题 28 DIP、minimap 44 DIP、全局状态栏 24 DIP；尺寸集中为共享资源。工具栏与标签不换行，窄窗口仍可使用导航、规则、主题与文件筛选。
- 取消顶部关系提示的伸展描边卡片，工具按钮使用轻量表面，差异前后导航与计数组成紧凑功能组。文件类型、标签差异数量与侧别采用中性色；颜色优先用于真实差异、焦点和必要警告。
- 浅色主题采用中性灰，深色采用中性石墨；正文和详情实色不透明。阴影仅用于菜单、minimap 真实预览等浮层，不给正文、单元格和普通按钮叠加效果。主题资源键一致，保留跟随系统和可见手动切换入口。
- 文本正文默认 13.5 DIP、行高 24 DIP，移除未修改行的横向装饰线。Excel 保留弱网格、原始行列、单元格差异与完整内容；Word 保持无行号逻辑文档视图。
- 详情折叠时仅占 28 DIP，提供清晰可键盘操作的展开入口及当前行号/单元格地址；文本首次默认折叠，其首次展开整体高度为 124 DIP；Excel 首次展开内容区默认 76 DIP，连同标题条的整体默认高度为 104 DIP。展开状态与展开整体高度分别按 text/spreadsheet 格式记忆；既有 DetailHeight 字段继续表示整体高度，旧值 72/124/180 等不额外叠加标题条，也不因默认值调整被覆盖，整体最小高度保持 72 DIP。高度可继续拖动，不把建议初始高度设为硬上限。切换选择不得导致自动展开或反复伸缩。
- 详情展开后仍支持双侧完整内容、片段高亮、字符级选择和复制；展开/收起不得影响正文选择、滚动同步及差异语义。Excel 工作表标签始终独立保留。
- Excel 当前单元格必须呈现清楚的四边选中轮廓，不能仅把底部网格线改色；轮廓采用固定尺寸、非命中测试覆盖层，不改变单元格测量、行高、文本基线或差异底色。BASE 与工作副本对应单元格同时可辨，键盘导航及虚拟化容器回收后不得留残框。
- BASE/MINE 身份、传入显示名称、完整路径和修订不得丢失；紧凑侧标题可以隐藏缺失修订的占位文案，完整信息通过工具提示保留。非阻断警告有明确入口，状态摘要省略零计数，规则变更必须可见。
- minimap 缩窄只改变视觉权重，保留真实双侧悬停预览、点击、连续拖动、滚轮、可视范围双向联动与像素桶聚合；不把短内容拉满全高。
- 保留文件/工作表持久视图、行列虚拟化及同步滚动。验证同视口前后画面、浅深主题、窄窗口、多标签、中文长名称、详情状态记忆及 100%/125%/150%/200% DPI，不以构建通过替代视觉验收。

### 14.9 视觉精修与统一尺度

用户于 2026-09-25 批准实施 `artifacts/design/2026-09-25-ui-polish-audit/Differ-视觉精修建议.md`。本轮只精修现有阅读界面，不改变区域顺序、Excel diff 工作流、数据模型或只读边界。

- 保持工具栏 38、文件标签 30、侧标题 28、minimap 44、状态栏 24 DIP。工具栏按现有顺序形成显示范围、查找/刷新/规则、差异导航、主题/更多功能组；同组间距 4、组间 12 DIP，图标按钮 32×28 DIP、图标视觉基准 14 DIP，导航组外沿与按钮等高，避免重复描边。
- 圆角按角色统一：数据格/分区 0、标签上角 4、按钮/输入框 6、菜单/预览浮层 8 DIP。几何与字号集中为共享资源；浮层以外不添加阴影，浮层阴影模糊 14、偏移 3 DIP，浅色/深色不透明度分别 0.12/0.22。

- 浅深主题使用中性阅读表面，正文和详情同色；单元格网格弱于结构分隔。普通网格和分隔为 1 DIP，行号差异条为 3 DIP，当前单元格保持 2 DIP 四边非布局覆盖轮廓。活动标签使用正文同色与半粗文字，差异计数与格式图标保持中性。
- 新增、删除、修改单元格使用极浅语义背景，变化片段使用有足够对比的语义前景与半粗字重；未变化片段保持普通正文色，不叠加第二层片段背景。行号标记、语义底色、变化片段以及颜色之外的状态信息均须保留。
- minimap 保持完整命中区域和现有交互；普通笔画约 1 DIP、差异笔画约 1.5 DIP，悬停笔画不超过 2 DIP，横向局部放大约 25%。内容笔画弱于差异边点，当前可视范围使用中性低对比提示；真实双侧预览、连续拖动和像素桶聚合保持不变。
- Excel 详情初始整体高度采用第 14.8 节的 104 DIP，标题 28 DIP。6 DIP 分隔拖动区仅显示一条细线；已有手动高度不覆盖，展开、字符级选择复制和全量内容不丢失。底部工作表栏常态 28 DIP、标签 26 DIP；文件标签栏常态 30 DIP，两类标签仅在横向溢出时增加滚动条所需高度，始终保持单行、完整标签命中范围及原有选择逻辑。
- 验收使用同视口、同数据及同选择位置的前后画面，并覆盖浅深主题、100%/125%/150%/200% DPI、窄窗口、多标签、长中文、密集差异、选择轮廓、同步滚动、minimap 与详情状态记忆；不通过降低虚拟化或添加每格装饰效果换取外观。

## 15. 性能与缓存

- 参数校验和格式解析不得阻塞 UI 线程。
- 先显示窗口和两侧文件信息，再在后台解析内容。
- 解析结果到格式专用展示模型的转换也必须在后台完成；UI 线程只允许原子绑定已经构造完成的不可变展示结果，不得在解析完成回调中逐行、逐单元格创建展示对象或计算列宽。
- 同时进行的解析与展示模型构建任务最多为两个；当前选中的文件标签拥有最高调度优先级，关闭标签后排队或运行中的任务必须取消，过期结果不得回写 UI。
- 文件标签内容采用按需创建和会话级持久化：每个文件只创建与实际格式对应的一套视图，第一次选中后保留到标签关闭；标签切换不得卸载并重新创建已访问视图。
- Excel 工作簿中每个已访问工作表的双栏表格视图按需创建并保留到文件标签关闭，必须保留该表的动态列、选择、滚动位置和详情状态；未访问工作表不得提前创建 WPF 视觉树。
- 文件标签或工作表关闭/释放时，必须同步移除持久视图、事件订阅、计时器、待处理 Dispatcher 操作和缓存引用，确保会话快照与视觉对象可回收。
- 左侧差异缩略概览必须使用常量数量的 WPF 视觉元素并通过绘制或像素桶聚合表达大量行；禁止为每个逻辑行创建 `ListBoxItem`、`Border` 等独立控件。
- 若引入缓存，缓存键至少包含两侧路径、文件长度、时间戳、内容哈希、解析器版本和设置。
- 解析缓存保存在应用专用缓存目录，不放进 SVN 工作副本或 TortoiseSVN 临时目录。
- 缓存应有容量和过期策略。
- 大文件阈值必须集中配置，不能散落硬编码。
- 文本整文件读取采用保守的 64 MiB 上限，并为解码字符数、行数及表格展开量建立集中预算；超限必须解释限制，不尝试分配接近 2 GiB 的单个字节数组。以代表性文件验证预算和取消响应。
- 二进制比较的文件大小上限和行宽同样集中配置；两侧字节相同时必须短路返回，不执行行对齐。
- 在确定阈值前应使用真实代码、Word 和 Excel 测试文件做基准测试。
- 取消的任务不得更新 UI 或写入有效缓存。
- Excel 工作表切换只更新当前工作表的展示集合，不得同步重建隐藏的代码、文本或通用差异集合。
- WPF 列表数据切换必须采用批量替换或单次属性通知，避免逐项 `Clear`/`Add` 触发成百上千次 UI 更新。
- Excel 左右表格的动态列应按工作表缓存并复用；只有列集合或列宽策略实际变化时才允许重建列。
- 工作表切换后的选中单元格、左右选择和滚动同步必须合并到一次布局后的更新，避免重复 `ScrollIntoView`。
- 文本、Word 和 Excel 的差异导航必须使用预计算索引，不得在每次查询当前位置或点击上下一个差异时重新筛选全部展示行。
- 性能日志只记录文件类型、大小、阶段耗时、缓存命中和释放结果，不得记录正文、单元格值、完整路径或命令行内容。
- Release 构建在本机使用代表性临时副本预热后，10 个已加载文件标签循环切换的 p95 应不超过 80ms、单次不超过 150ms；10 个已访问 Excel 工作表循环切换的 p95 应不超过 100ms、单次不超过 180ms；后台加载其他文件时不得出现超过 200ms 的 UI 无响应。
- 对超大段落或表格行序列，差异算法必须先剥离连续相同前缀/后缀，并在候选矩阵超过集中配置的阈值时使用线性锚点对齐，禁止为 12000 行级别输入分配平方级 LCS 矩阵。
- Word 仅在小文档或受限长度的修改段落内执行文字级差异；超大文档保留段落级准确结果，过长修改内容以完整双侧文本展示，避免首次打开被单段文字比较拖住。
- Excel 双栏表格必须保持行列虚拟化和容器回收；滚动条滑块拖动期间正文必须实时更新，不得等到释放鼠标后才刷新。两侧滚动同步应在每个渲染周期合并为一次最新位置更新，避免为同一帧内的每个像素重复布局。
- 性能优化不得改变统一差异模型、行对齐、空白上下文、单元格内差异片段或底部完整详情区。
- 12000 行压力工作簿验证使用原件的隔离副本或 TortoiseSVN 提供的真实 BASE/MINE 快照，分开记录双侧解析、模型比较、展示构造与 UI 选择/滚动/切表耗时及分配；不得用相同文件短路、减少工作表/行列或取消未修改上下文代替优化。可对内容与地址完全相同的不可变展示数据复用、对饱和列宽停止冗余测量，但不得改变差异数量、原始坐标、工具提示或复制结果。
- 未变化单元格应使用 WPF TextBlock 的纯文本快路径，避免为每个可见普通值建立富文本 Inline/TextContainer。地址解析、元数据字典容量与节点 SectionKey 初始化可以消除冗余分配，结果必须与原管线逐单元格语义摘要一致。
- 表格可见单元格使用可回收的轻量内容宿主，通过一次完整单元格展示对象绑定同步文字、语义背景和工具提示，避免嵌套 ContentPresenter 与每格重复的状态 Binding；不改变字体、内边距、选中轮廓、复制和双侧滚动。回收时必须清空旧内容/旧差异色，主题切换仍动态生效；保留行列虚拟化并用真实压力表重复测量冷建表及滚动耗时。

Open XML 文档属于 ZIP 包。解析时必须限制异常压缩比例、部件数量和解压后总量，防止恶意或损坏文件导致内存耗尽。

## 16. 安全与隐私

- 默认完全离线。
- 不上传文件、差异、文件名或 SVN 地址。
- 不执行宏、脚本或文档内嵌对象。
- 不记录文档正文。
- 不记录 SVN 密码、令牌或认证头。
- 外部调用参数不得再次通过 shell 字符串解释。
- Differ 不负责删除 TortoiseSVN 提供的临时 BASE 文件。
- Differ 自建的会话快照使用随机隔离目录；关闭对应文件标签时立即清理，应用退出时清理全部活动会话，异常退出遗留目录在后续启动时按过期策略清理。
- 会话判重必须包含两侧实际快照的内容哈希，不能仅凭长度和修改时间复用旧结果。单实例转交的总超时须覆盖连接、发送和确认等待，主实例失去响应时次进程必须退出等待并给出错误。
- 比较解析以只读方式打开所有输入；代码/普通文本保存必须遵守第 27 节的来源确认、指纹检查及原子写入要求。
- 对目录路径、设备路径和不可读文件做明确校验。
- 集成配置备份不得包含文档内容或 SVN 凭据。

未来增加云端或 AI 能力时，必须作为新的产品范围获得确认，并更新本节。

## 17. 错误处理与日志

### 17.1 用户错误

用户界面错误信息应包含：

- 发生了什么。
- 哪个文件或步骤受影响。
- 是否仍可查看其他差异。
- 用户下一步可以做什么。
- 可复制的技术详情入口。

### 17.2 日志

建议使用结构化日志并保存在用户本地应用数据目录。日志可记录：

- 应用版本。
- TortoiseSVN 检测结果和 Differ 调用模式。
- 操作类型和耗时。
- 文件类型、文件大小和匿名化错误上下文。
- 异常堆栈。

日志不得记录：

- 文档正文或单元格内容。
- 提交密码、令牌、Cookie 或证书私钥。
- 未经处理的完整命令行认证参数。

日志应滚动并限制保留数量。

Release 版本持久化不含内容、完整路径或原始异常消息的诊断事件（事件号、类型、受控说明和异常类型），并保留受限的性能日志；无参数集成页提供版本、构建标识、运行时及解析器版本，便于核实实际部署。不得为日志采集文档内容。

## 18. 测试规范

### 18.1 单元测试

必须覆盖：

- TortoiseSVN 命名参数、可选参数、未知参数、双路径兼容入口和 6 个位置参数的旧版协议。
- BASE、MINE、显示名称、修订和原始文件名映射。

- 行级、词级差异。
- Word 段落、列表、表格和修订标记。
- Excel 工作表、行插入、单元格值、公式和格式。
- Excel 插入一行后，对齐成功且内容不变的后续行不计为移动或任何差异；单元格显示值相同但语义类型变化时计为修改。
- Word 内容控件（SDT）包裹的段落和表格仍应参与比较，无法解析的块级结构应产生警告而不是静默丢弃。
- 二进制字节级比较：相同文件直接判定相同；单字节修改只产生字节粒度片段高亮；插入字节段后后续行保持对齐；超过大小上限报错；文本适配器探测出二进制内容时回退到二进制适配器。
- `.xlsm` 相同内容零差异且 VBA 部件被忽略；`.xls` 行插入对齐、单元格值与公式变化；`.doc` 段落变化检测；`.csv` 引号转义、引号内换行、行插入对齐与编码警告；`.rtf` 控制字剥离后中英文段落对齐。
- 集成配置备份文件损坏时应安全降级，不得使集成页崩溃。
- Word 与 Excel 仅发生格式变化时，默认不计为内容差异；显式启用格式比较后才计入。
- Excel 工作表分组、底部工作表标签顺序和每表差异计数。
- Excel 表格模型的统一列顺序、真实行号、空白单元格、行占位和单元格差异类型。
- 中英文、数字和公式文本的单元格内字符片段差异，且不得拆分 Unicode 文本元素。
- 不支持格式和损坏文件。

### 18.2 TortoiseSVN 集成测试

在隔离目录中覆盖：

- 为全局 `Diff` 生成正确的外部差异命令。
- 读取、备份、幂等安装和恢复模拟的全局配置。
- 安装时备份并清除全部受支持扩展名高级覆盖，使全局 `Diff` 对文本、Word、Excel 和 CSV 真实生效。
- 重复安装时把安装后新增的高级覆盖更新为恢复基线并再次清除。
- 恢复时不覆盖安装后重新配置的全局路径或高级扩展名工具。
- 不覆盖未备份的现有第三方全局差异工具配置。
- 使用 TortoiseSVN 或等价参数启动 Differ 后正确显示 BASE/MINE。
- 连续启动多个 Differ 外部差异进程时，后续请求进入同一主窗口的不同文件标签，转交进程退出后会话快照仍可读取。

- 关闭 Differ 后不改变工作文件、SVN 状态或 TortoiseSVN 提交选择。
- 中文、空格和长路径。

自动化测试不得修改当前用户真实的 TortoiseSVN 设置。真实端到端验证必须先备份目标配置，并且只使用 `测试用例` 的副本。

### 18.3 Office 回归测试

- 中文和英文。
- 空文档/空工作表。
- 大表格和大工作表。
- 合并单元格。
- 公式变化但值不变。
- 值变化但公式不变。
- Word 表格插行。
- Word 未接受修订。
- 损坏、加密或异常压缩文件。

### 18.4 现有测试用例

本机 `测试用例` 是人工验收来源，原件不进入GitHub源码提交。默认自动测试必须自行生成代表性样本或使用仓库内明确许可的最小fixture，不依赖本机业务原件；针对业务原件的单独人工回归必须复制后再制造差异，不得原地覆盖。

### 18.5 视觉验证

WPF 界面变化至少验证：

- 100%、125%、150% 和 200% DPI。
- 浅色和深色主题。
- 中文文件名和长路径。
- 窄窗口与最大化。
- 大型文件和大量差异节点。

- 首个窗口必须直接使用当前 Windows 主题显示；运行期间系统主题变化和工具栏手动切换都应即时更新全部视图，不得产生浅色闪烁、缺失资源、布局跳动或临时诊断文件。

## 19. 编码规范

- 启用 Nullable Reference Types。
- 启用隐式 using，但公共项目应保持引用清晰。
- 生产代码不得忽略编译器警告而不说明原因。
- 公共异步方法以 `Async` 结尾，并接收 `CancellationToken`。
- 除 WPF 事件处理器外禁止 `async void`。
- 文件和网络 I/O 不得在 UI 线程同步执行。
- 类和方法保持单一职责。
- 依赖通过构造函数注入。
- 不使用 Service Locator。
- 不使用全局可变单例保存当前差异会话状态。
- 用户可见字符串进入资源文件，不散落在代码中。
- 注释解释“为什么”，不重复代码已经表达的“做什么”。
- 捕获异常时保留原始异常作为内部异常。
- 禁止空的通用 `catch`。
- 所有临时资源使用确定性释放。
- 时间持久化使用 UTC，界面显示转换为本地时区。

- 每次发布通过 `scripts\publish.ps1` 重新生成并覆盖稳定目录；发布前必须确认没有 Differ 进程正在占用目标文件。脚本必须先完成 `win-x64` 依赖还原，再发布到受控暂存目录，验证暂存可执行文件后才可替换稳定目录；依赖还原、发布或网络失败不得先删除当前可用版本。
- TortoiseSVN 全局 `Diff` 必须指向稳定目录中的 `Differ.App.exe`，避免功能迭代后因目录名变化反复修改调用路径。
- 程序程序集、文件和信息版本仍随功能变更正常递增；“只保留一套发布副本”不等于冻结内部版本号。

不优先追求将程序本体打成单文件。安装包采用第 20.4 节定义的离线分发形式，程序仍以完整自包含目录运行。自动更新和资源管理器右键集成暂不加入。

### 20.5 每次任务结束的目录清理（2026-10-24 用户明确要求）

用户已授权清除无意义的重复产物，并要求每次任务完成后项目路径保持干净；此要求是开发交付的一部分，不得再次把临时副本留给用户手工检查。

默认用 `scripts/verify-and-clean.ps1` 完成 Release build/test、格式检查与 finally 清理；日志及 TRX 写项目外，任一步失败仍返回失败。历史 `artifacts/design` 等引用的实际位置见 `docs/ARCHIVE_INDEX.md`。

- 项目内保留原始源码/项目/脚本、规范与简明交付文档、原始测试用例、必要构建输入、`.svn`、唯一正式 `artifacts/publish/Differ-win-x64`、最新 `artifacts/installers` 与仍被打包脚本使用的 `artifacts/packaging` 工具输入。
- 历史源码快照、性能基线、原始事件/截图/TRX及故障恢复备份移到项目外有清单的归档。只保留文档需要的小型当前效果图或归档入口；更新活跃引用，不保留指向已迁移目录的失效使用说明。同盘归档移动不计为磁盘释放。
- `bin/obj`、Python `__pycache__`、临时运行副本、探针下载/解包副本和打包暂存属于可重建输出。先完成必要验证，再清理；下一次构建可重新产生，但不能作为本次任务交付残留。正式运行文件不得按同名或哈希跨目录自动删除。
- 测试截图、性能日志及临时工作材料默认写项目外的临时/维护目录，允许显式指定输出路径；不得每次测试自动生成新的 `artifacts/visual-validation` 等历史树。需要保留时归档，结束时清理任务临时运行进程和文件。
- 安装包编译成功或失败都收尾删除本次 `tooling/build` payload；保留项目外构建日志与清单。发布必须先验证新产物，替换失败恢复旧正式目录，正常结束不留下 staging/previous 并列副本。
- 每次任务结束执行 `pwsh -NoProfile -File scripts/clean-workspace.ps1 -Apply`，再执行同脚本 `-Check`。`-Apply` 只处理有明确白名单和路径边界的可重建输出；未知目录只报告，由当前任务分类处理后再交付。`-Check` 不通过不能宣称收尾完成。
- 任何递归删除/移动前验证最终绝对路径、保护目录及重解析点，发现正在使用候选目录的进程时停止清理，不强杀用户进程。保存操作清单和前后体积；`.svn`、用户文件、许可、离线依赖和源码不可作为缓存删除。不自动执行 SVN add/delete/revert/commit。

## 24. 规范变更流程

### 24.1 触发条件

发生以下任一情况时必须更新本文档：

- 用户改变功能范围或工作流。
- 发现既定方案无法可靠实现。
- 更换目标框架、UI 框架、SVN 接入方式或核心依赖。
- 改变 BASE/MINE、外部调用或提交边界语义。
- 增加新的文件格式。
- 改变安全、隐私、缓存或日志行为。
- 测试发现规范本身存在错误或遗漏。

### 24.2 版本规则

- 文字澄清、错别字、不改变行为：补丁版本，例如 `1.0.1`。
- 新增兼容功能或扩充规范：次版本，例如 `1.1.0`。
- 改变核心架构、数据语义或兼容性：主版本，例如 `2.0.0`。

### 24.3 同步步骤

1. 修改受影响章节。
2. 更新文档版本和最后更新时间。
3. 在变更记录中说明原因和影响。
4. 检查 `AGENTS.md` 是否也需要调整。
5. 更新相应测试和验收标准。
6. 将规范与实现放入同一个 SVN 提交。

若变化会显著扩大范围或改变用户数据、提交行为，必须先征得用户同意。
